# 跨项目本地搜索实施计划

> 状态：可开始 M1-A
> 对应 Spec：[M1：跨项目本地搜索](../specs/20260802-02-跨项目本地搜索.md)
> 基线：`dev` / CodeShelf v0.1.44（2026-08-02）

## 实现原则

- 只实现 Spec 中的文本、正则和文件名搜索，不混入 M2 依赖解析或 M6 AI 增强。
- 前端只提交书架项目 ID，后端从 SQLite 解析项目根路径并执行全部路径校验。
- 搜索不依赖 Node sidecar、AI Shell 或用户自行安装的 `rg`。
- 文件列表、文件内容、事件批次和前端结果均有界，不一次收集完整仓库。
- 一个项目失败不阻塞其他项目；所有结束路径都形成唯一终态。
- 每完成一阶段立即运行对应验证，不在最后一次性补测试。

## 类型与命令

### Rust 数据类型

所有跨端字段使用 `serde(rename_all = "camelCase")` 和 `specta::Type`。

建议类型：

```text
ProjectSearchRequest
  searchId: String
  projectIds: Vec<String>
  mode: Text | Regex | Filename
  query: String
  caseSensitive: bool
  fileGlobs: Vec<String>
  includeUntracked: bool

ProjectSearchMatch
  projectId / projectName / relativePath
  line / column / preview
  previewTruncated / encodingLossy
  source: GitTracked | GitUntracked | Filesystem

ProjectSearchEvent
  searchId
  kind + 对应载荷
```

事件使用 `#[derive(tauri_specta::Event)]`，并在 builder 上注册 `collect_events![ProjectSearchEvent]`。该类型名会导出为 `project-search-event`，前端使用生成的 `events.projectSearchEvent.listen(...)`，避免手写两份事件载荷类型。

### Tauri 命令

```text
start_project_search(request) -> ProjectSearchAccepted
cancel_project_search(search_id) -> ()
open_project_search_result(project_id, relative_path) -> ()
```

- `start` 在结构校验、正则编译和任务槽认领完成后立即返回，后台任务发送事件。
- 前端先注册类型化事件，再调用 `start`；`searchId` 由前端预先生成，用于过滤同名全局事件。
- `cancel` 只有 owner ID 一致时才设置取消并终止登记中的 Git 子进程。
- `open` 重新查询项目和编辑器配置，拒绝绝对路径、`..`、符号链接和根目录外目标。

每次命令或事件签名变化后运行：

```bash
cd src-tauri && cargo test --lib export_bindings
```

## 任务状态机

全应用一个任务槽，结构至少表达：

```text
Empty
Running
  ownerSearchId
  cancelled
  gitPids[]
```

实现要求：

1. 一把同步锁内完成“是否空闲 + 写入 Running”，不在异步间隙留竞态。
2. Git 子进程启动后只在 owner 仍一致时登记 PID。
3. 取消在同一锁内核对 owner、设置标记并复制待清理 PID，锁外执行 `kill_tree`。
4. 后台任务结束只在 owner 仍一致时释放槽位。
5. 事件发送失败不阻止释放；错误路径和 panic-free 后台任务都必须收尾。
6. 真正退出应用时同步标记取消并清理登记中的所有 Git PID。

用独立测试锁隔离全局状态机测试，覆盖并发认领、旧 owner 释放和错误 ID 取消。

## 搜索流水线

### 1. 请求准备

- 校验 `searchId`、项目数、查询字符数、glob 数量与长度。
- 项目 ID 去重但保持原顺序；不存在 ID形成项目级失败。
- 文本模式使用 `regex::escape` 后编译；正则模式直接编译；统一应用大小写选项。
- 文件名模式编译为规范化相对路径上的字面量匹配。
- 资源常量由后端固定，前端不能覆盖。

### 2. 项目调度

- 用固定并发 2 调度项目，代码中保留不超过 4 的硬守卫，不在设置页暴露。
- 整体和单项目时间预算在调度、文件、读取块之间协作式检查。
- 阻塞文件系统工作进入受控 blocking 线程；不要在 async runtime worker 上直接遍历大目录。
- 操作系统已阻塞的文件/NAS 读取无法硬中断，不能释放 owner 后让旧线程与新搜索并行输出；等 worker 真正退出后再释放。

### 3. Git 文件枚举

- 直接存在 `.git` 的项目使用 `git -C <root> ls-files -z --cached`。
- 开启未跟踪时增加 `--others --exclude-standard`，来源需要区分 tracked/untracked；可分两次枚举后流式合并去重。
- 使用参数数组启动 Git，不经过 Shell，不拼接用户查询。
- stdout 按 NUL 边读边消费，不能使用 `Command::output()` 收集完整路径列表。
- stderr 固定上限；子进程经过 `process_guard::configure_std`，登记 PID 后再读取。
- 父项目不进入子模块；单独加入书架的子模块按自己的 `.git` 搜索。

### 4. 非 Git 文件枚举

- 使用 Rust `ignore::WalkBuilder`，遵循根目录 `.gitignore` 和嵌套规则。
- 不跟随符号链接；隐藏文件不因“隐藏”本身被排除，只由 ignore/生成目录规则决定。
- 默认排除 `.git`、`node_modules`、`target`、`dist`、`build`、`.next`、`.cache`、`coverage` 目录。
- 枚举结果逐个送入匹配器，不先收集 `Vec<PathBuf>`。

### 5. 路径校验

- 归一化相对路径分隔符为 `/`，拒绝绝对路径和 `..`。
- 使用 `symlink_metadata` 先跳过符号链接，再对实际文件做根目录包含校验。
- glob 只做包含过滤，最多 16 条；编译失败在启动阶段报错。
- 同一路径只处理一次；搜索结果永远不携带绝对路径。

### 6. 内容匹配

- 文件大小大于 8 MiB 时内容模式跳过；文件名模式仍可匹配路径。
- 使用固定读取块检测首块 NUL；内容模式逐行读取，但单行缓冲最多 64 KiB。
- 超长行停止累积并排空到换行，整行不产生结果。
- 非法 UTF-8 用有损字符串匹配和预览，并设置 `encodingLossy`。
- 同一行只返回第一个命中位置；行列按从 1 开始的 Unicode 字符位置计算。
- 预览最多 4 KiB，截断发生时设置标志。

### 7. 事件与上限

- 每批最多 50 条或约 50 ms 发送；取消后不再发送新 match。
- 单项目 500 条后停止该项目并标记项目截断。
- 全局 2,000 条后设置全局取消原因，终态为 `truncated`。
- 项目失败发送 `projectFailed`，正常项目继续；结束时只发送一个 `finished`。
- 前端按 `searchId` 过滤事件，卸载时先取消监听再清理局部结果。

## 编辑器打开

`open_project_search_result` 的收敛流程：

1. 通过 crate 内项目 helper 查询 `projectId`。
2. 校验 `relativePath` 是规范化相对路径并解析到项目根内的普通文件。
3. 调用现有 `settings::get_editors()`；项目 `editorId` 命中优先，否则取 `is_default`，再退第一项。
4. 将已验证文件路径和配置中的编辑器路径传给现有 `system::open_in_editor`。
5. 没有编辑器配置时沿用 `open_in_editor` 的平台默认。

M1 不拼 `--goto`、`--line` 等编辑器私有参数。复制动作在前端生成“绝对文件路径:行号”，绝对路径只来自书架项目根 + 后端结果相对路径。

## 分阶段实施

### M1-A：协议与状态机

- 新增 Rust 类型、类型化事件、3 个命令骨架和任务槽。
- 注册 commands/events，导出 bindings。
- 后台任务先发送受控 started/finished，不扫描文件。
- 测试并发认领、owner 取消、owner 释放和唯一终态。

完成标准：Rust 测试、bindings 导出、`npx tsc --noEmit` 均通过。

### M1-B：Git 已跟踪文件

- NUL 流式枚举 tracked 文件。
- 完成三种匹配模式、文件/行/预览限制与分批事件。
- 补中文、空格、二进制、超长行和结果截断测试。

完成标准：真实 Git 项目默认只出现 tracked 命中，取消不遗留 Git 进程。

### M1-C：未跟踪与非 Git

- 增加 untracked 枚举及来源标记。
- 增加 `ignore` walker 和生成目录排除。
- 补符号链接越界、路径失效、权限失败和部分成功测试。

完成标准：非 Git 项目正常参与；一个坏项目不会阻断其他项目。

### M1-D：书架覆盖层

- 增加入口、范围选择、查询选项、进度、分组结果和取消。
- 使用生成的 type-safe events，确保先监听后启动。
- 实现打开文件与复制路径；不做编辑器跳行。

完成标准：无 AI Provider 环境完整可用，现有书架筛选行为未变化。

### M1-E：边界与实机验证

- 运行 Spec 的真实项目样本矩阵。
- 验证 50 个项目、部分路径失效、取消、时间预算和全局上限。
- Windows 实机验证中文/空格路径、进程清理和编辑器打开。

完成标准：Spec 的验收项全部有自动检查或人工记录，再将路线图 M1 标为完成。

## 每阶段验证

按实际改动运行：

```bash
npx tsc --noEmit
cd src-tauri && cargo check
cd src-tauri && cargo test --lib
cd src-tauri && cargo test --lib export_bindings
npm run build
```

- M1-A：Rust 测试 + bindings + tsc。
- M1-B/C：Rust check/test + bindings + tsc；新增依赖后跑完整 build。
- M1-D：tsc + Rust 回归 +完整 build。
- M1-E：全部命令 + Windows 实机验证。

本计划不新增 Windows `#[cfg]` 分支，通常不触发 Docker 交叉编译门禁；如果实现时修改 `process_guard` 或其他 Windows 专有代码，必须追加 Docker 交叉编译。
