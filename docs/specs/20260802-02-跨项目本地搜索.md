# M1：跨项目本地搜索

> 状态：技术审核完成，可进入实现
> 上位路线图：[书架能力演进路线图](20260802-01-书架能力演进路线图.md)
> 实施方案：[跨项目本地搜索实施计划](../plans/20260802-01-跨项目本地搜索实施计划.md)

## 背景

CodeShelf 现有书架搜索只按项目名称和路径过滤，不能查看仓库内部文件。项目对话和简历 Agent 虽然各有文件搜索工具，但它们属于 AI 会话或 Node sidecar；书架的基础搜索不能因此依赖 AI 配置、模型服务或 sidecar 存活。

M1 新增一个独立的本地搜索任务：只读取已经加入书架的项目，提供明确文本、正则和文件名搜索，并具备取消、错误隔离和资源上限。依赖清单查询在 M2 实现，不混入本阶段。

## 现状依据

| 现有事实 | 参考位置 | 结论 |
|---|---|---|
| 书架输入框只筛选项目名/路径 | `src/pages/Shelf/index.tsx` | 现有输入框语义保持不变 |
| 项目数据来自 SQLite | `src-tauri/src/commands/project.rs` | 搜索范围以项目 ID 表达，项目根目录由后端解析 |
| 编辑器接口只支持打开路径 | `src-tauri/src/commands/system.rs` | M1 不承诺编辑器跳转行号 |
| 敏感规则当前服务于背景知识生成 | `src/pages/Toolbox/ResumeGenerator/SensitiveFileRulesDialog.tsx` | 不直接套到纯本地搜索，避免漏掉测试、CI 和应用配置 |
| 已有取消和进程树回收能力 | `src-tauri/src/commands/git/clone.rs`、`src-tauri/src/process_guard.rs` | 新搜索任务必须达到相同的所有权与清理标准 |

## 目标

- 在全部书架、指定分类或手选项目中搜索明确文本、正则和文件名。
- Git 项目默认只搜索已跟踪文件，用户显式开启后才包含未跟踪且未忽略的文件。
- 非 Git 项目也能通过受控文件遍历参与搜索。
- 结果按项目和文件分组、分批显示，并允许中途取消。
- 单项目失败不终止其他项目；完成、部分失败、取消、超时和截断必须明确区分。
- 内存使用由并发、单文件/单行缓冲和结果上限控制，不随累计读取内容线性增长。
- 没有任何 AI Provider 时完整可用，执行过程不触发模型或网络请求。

## Non-Goals

- 不做依赖和运行时清单搜索；该能力属于 M2。
- 不做自然语言、语义搜索、Embedding、向量库或 AI 自动扩词。
- 不建立全量内容索引，不保存查询历史和搜索结果。
- 不做跨项目替换、批量编辑或自动修改代码。
- 不启动 LSP，不承诺定义、引用和调用关系分析。
- 不搜索 Git 历史、提交内容、子模块内部仓库或被忽略文件。
- 不要求用户额外安装 `rg`。
- 不复用 AI Shell 或简历 Agent 作为搜索服务。
- 不在 M1 建立通用编辑器跳行能力。

## 产品决策

### 入口

- 首版从书架现有“更多”菜单进入“跨项目搜索”，打开书架内全屏覆盖层。
- 不增加侧边栏一级导航；跨项目搜索仍属于书架能力。
- 不改变现有“搜索项目名称或路径”输入框的行为。
- 从指定分类打开时以该分类为初始范围，从“全部”打开时以全部项目为初始范围。
- 关闭运行中的搜索覆盖层时先取消任务；首版不支持关闭后在另一个页面继续查看结果。

### 查询历史

首版查询和结果只存在当前覆盖层内存，关闭即清空，不写 SQLite 或 JSON。只有真实使用反馈证明需要复用查询后，再单独设计历史数量和隐私策略。

### 编辑器操作

- 结果可在项目已配置编辑器中打开；没有项目级配置时沿用当前全局默认逻辑。
- 提供复制相对路径和“绝对路径:行号”。
- 当前编辑器配置允许任意编辑器，且没有参数能力描述，因此 M1 不猜测 `--goto` 等私有参数，不承诺跳转到行号。

## 搜索行为

### 查询模式

| 模式 | 含义 | 结果粒度 |
|---|---|---|
| 文本 | 对物理行做字面量匹配 | 同一行最多一条，列号指第一个命中 |
| 正则 | 使用本地确定性正则语义匹配物理行 | 同一行最多一条，无效表达式拒绝启动 |
| 文件名 | 对规范化项目相对路径做字面量包含匹配 | 每个文件最多一条，无行列和内容预览 |

- 文本和文件名默认不区分大小写，用户可以显式开启区分大小写。
- 正则的大小写选项在搜索开始前确定。
- 空查询拒绝启动。
- 路径在匹配与结果协议中统一使用 `/`。
- 用户可以增加最多 16 条文件 glob 作为包含过滤器；glob 不改变查询模式。

### 文件范围

| 项目类型 | 默认范围 | 开启“包含未跟踪文件”后 |
|---|---|---|
| Git 项目 | Git 已跟踪文件 | 已跟踪 + 未跟踪且未被 `.gitignore` 排除的文件 |
| 非 Git 项目 | 遵循 `.gitignore` 的受控遍历 | 行为不变，并说明没有 Git 跟踪状态 |

- Git 项目的定义沿用当前产品语义：书架项目根目录直接存在 `.git` 文件或目录。
- 书架项目只是父仓库的普通子目录时，按非 Git 项目处理，不能越过书架根目录。
- 不递归搜索父项目中的子模块仓库；子模块单独加入书架后可独立搜索。
- 首版不提供“包含被忽略文件”开关。
- 默认排除 `.git`、`node_modules`、`target`、`dist`、`build`、`.next`、`.cache`、`coverage` 等生成目录。
- 符号链接文件和目录首版均不跟随。

### 本地数据边界

- 搜索查询和内容预览只存在任务与覆盖层内存，不写搜索历史、不写入应用日志、不发网络请求。
- 日志只允许记录不含查询、预览和绝对路径的阶段、计数与错误类别。
- M1 不直接复用简历模块的敏感文件规则。该默认列表包含 `/test/`、`/.github/`、`application*.yml` 等正常代码检索目标，直接复用会造成不可见漏搜。
- M6 若将搜索结果发送给 AI，必须在出站边界重新应用敏感规则，并让用户预览实际发送范围。
- 如果未来需要纯本地搜索排除规则，应单独命名和设计，不能改变现有“背景知识敏感规则”的含义。

### 内容边界

- 文件内容必须逐块或逐行处理，不允许把所有项目内容或完整大文件长期保存在内存。
- 首个读取块包含 NUL 的文件按二进制跳过。
- 内容模式单文件上限 8 MiB；文件名模式仍可匹配普通大文件或二进制文件的路径。
- 单个物理行缓冲上限 64 KiB；超长行整行跳过，不能用局部内容产生误导命中。
- 单条预览最多 4 KiB，并标识预览或编码截断。
- 非法 UTF-8 可以使用有损预览，但必须标识 `encodingLossy`。
- 内容结果的行号和列号均从 1 开始；列号按用户可见字符计算。

## 资源与生命周期

### 首版固定上限

| 项目 | 默认/上限 |
|---|---|
| 同时搜索的项目 | 默认 2，不得超过 4 |
| 一次请求的项目数 | 200 |
| 查询长度 | 512 个 Unicode 字符 |
| 文件 glob | 16 条，每条 256 个字符 |
| 单项目结果数 | 500 |
| 全局结果数 | 2,000 |
| 结果事件批次 | 最多 50 条或约 50 ms 一批 |
| 单项目协作式时间预算 | 30 秒 |
| 整体协作式时间预算 | 120 秒 |

- 单项目达到 500 条后停止该项目，其他项目继续。
- 全局达到 2,000 条后停止整个任务，终态为“已截断”，不能显示为完整完成。
- 时间预算在项目、文件和读取块之间检查。操作系统已经阻塞的本地/NAS 文件读取无法保证硬中断，界面不得将其宣传为绝对硬超时。
- 前端最多保留协议允许的 2,000 条结果；分组默认折叠，展开时分段渲染。

### 任务生命周期

- 首版全应用同时只允许一个跨项目搜索任务。
- 每个任务有唯一 `searchId`，启动、事件、取消和终态均携带或核对该 ID。
- “检查是否空闲”和“认领任务”必须是原子操作；并发启动只能有一个成功。
- 取消只能作用于 ID 匹配的任务；旧任务结束不能清掉新任务状态。
- 取消在项目、文件、读取块和结果批次之间生效，并终止仍在运行的 Git 枚举子进程。
- 窗口关闭只隐藏到托盘时任务继续；应用真正退出时清理任务及其子进程。
- 所有结束路径只产生一个终态，并释放任务所有权。

## 逻辑协议

本节定义前后端必须共享的数据含义，不限定具体代码组织。

### 请求

```text
searchId
projectIds[]
mode: text | regex | filename
query
caseSensitive
fileGlobs[]
includeUntracked
```

- 前端只提交项目 ID，不提交任意项目根路径。
- 并发数、时间和结果上限由后端固定，不能由前端放大。
- 项目 ID 去重后不能为空；不存在的项目形成项目级失败，不能解析为其他路径。

### 匹配结果

```text
projectId / projectName
relativePath
line / column
preview
previewTruncated / encodingLossy
source: gitTracked | gitUntracked | filesystem
```

- `projectName` 是任务开始时的显示快照。
- 结果不携带绝对路径；打开文件时必须按 `projectId + relativePath` 重新验证当前项目根目录。
- 来源不同但指向同一文件的结果需要去重。

### 事件与终态

事件至少覆盖：任务开始、项目开始、结果批次、项目完成、项目失败和任务结束。

终态包括：

- `completed`：所有参与项目正常结束。
- `partial`：至少一个项目成功、至少一个项目失败。
- `cancelled`：用户取消。
- `timedOut`：整体时间预算触发。
- `truncated`：达到全局结果上限。
- `failed`：所有项目均失败或任务无法继续。

用户取消、整体超时和全局截断优先作为主终态，汇总中仍保留此前项目失败。一个项目失败不能终止其他项目。

## 错误与状态展示

- 空查询、无效正则、请求超限和已有任务运行属于启动失败，不创建后台任务。
- 路径失效、无权限、Git 枚举失败和单文件读取失败属于项目或文件级问题，不中止其他项目。
- Git 命令不可用时，Git 项目标记失败；不能静默改为扫描整个工作区并声称等价。
- 文件在搜索期间被删除属于跳过项；大量变化时提示“搜索期间项目发生变化”。
- 界面同时显示匹配数、完成项目数、失败项目数、跳过文件数和取消/超时/截断状态。
- 错误文案必须是具体中文，并兼容 Tauri 返回纯字符串错误的现状。

## 影响面

- 前端：书架入口、独立搜索覆盖层、查询范围、类型化事件聚合、结果分组与打开文件。
- Rust：搜索协议、任务状态、项目读取、文件枚举、内容匹配、取消和退出清理。
- 项目读取：复用现有 SQLite 项目查询，不复制同义 SQL，不新增同义项目命令。
- 编辑器：复用现有项目级和全局默认编辑器配置；文件路径必须在后端重新校验。
- 类型：新增 Tauri 命令和事件后重新生成 `src/bindings.ts`，禁止手改。
- 依赖：允许增加支持 `.gitignore` 语义的 Rust 依赖；不得删除根 `package.json` 中 sidecar 使用的 JavaScript `ignore`。
- 存储：不改项目表、设置和 JSON 文件，不新增 migration。
- AI：不改 Provider、Chat、Resume 或 Node sidecar 协议。

约束结论：

| 项目 | 结论 |
|---|---|
| Windows 专有代码 | M1 不计划新增专有分支；仍需 Windows 实机验证路径、取消和编辑器打开 |
| 应用数据写入 | 无，只读 SQLite 和项目文件 |
| Tauri 签名 | 有新增，必须导出 bindings |
| 前端轮询 | 无，使用事件 |
| AI 依赖 | 无 |

## 验收方式

### 自动验证

- 查询：文本/正则/文件名、大小写、无效表达式和 glob。
- 路径：中文、空格、父目录、符号链接、项目失效和非 Git 项目。
- 内容：UTF-8、无效 UTF-8、二进制、大文件和超长行。
- 状态机：并发启动、错误 ID 取消、旧任务释放、唯一终态和应用退出清理。
- 资源：单项目/全局结果、事件批次、文件/行/预览上限。
- 终态：完成、部分失败、取消、超时、截断和全部失败。

按影响运行：

```bash
npx tsc --noEmit
cd src-tauri && cargo check
cd src-tauri && cargo test --lib
cd src-tauri && cargo test --lib export_bindings
npm run build
```

### 人工验收

至少使用以下真实项目组合：

1. Git 项目：已跟踪命中、未跟踪命中和 `.gitignore` 排除文件。
2. 非 Git 项目：嵌套目录和 `.gitignore`。
3. 异常项目：书架路径失效或无权限。
4. 中文、空格和大小写相近路径。
5. UTF-8、非法 UTF-8、二进制、大文件和超长行。
6. 已跟踪的测试、CI、应用配置和 `.env` 样本。

必须确认：

- 清空 AI Provider 后三种搜索完整可用，没有模型或网络请求。
- 默认不出现未跟踪命中，开启开关后出现；被 `.gitignore` 排除的文件仍不出现。
- 已跟踪的测试、CI 和应用配置可被本地搜索，查询和预览不写日志。
- 取消后形成 `cancelled`，Git 子进程退出，随后可再次搜索。
- 一个项目失败时其他项目继续，最终显示 `partial`。
- 达到结果上限时明确显示截断。
- 点击结果打开正确文件；复制的相对路径和行号正确。
- 隐藏到托盘时任务继续，真正退出应用时子进程被清理。
