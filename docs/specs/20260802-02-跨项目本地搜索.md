# M1：跨项目本地搜索

> 状态：技术审核完成，可按本文开始实现
> 上位路线图：[书架能力演进路线图](20260802-01-书架能力演进路线图.md)
> 范围：只包含 M1 本地文本、正则和文件名搜索；依赖搜索属于 M2

## 背景

CodeShelf 现有书架搜索只在前端按项目名称和路径过滤，不能查看仓库内文件。项目对话和简历 Agent 虽然各有文件搜索工具，但它们属于 AI 会话或 Node sidecar：没有配置 AI 时不应成为书架搜索的运行依赖，而且现有 `grep` 会将单个文件完整读入内存，不符合跨多个项目搜索的资源边界。

M1 因此不是对现有输入框增加一个 `grep` 调用，而是新增一个独立的、可取消、有硬上限的本地搜索任务。它只读取已经加入书架的项目，不调用 AI，不保存文件内容索引。

## 现状依据

| 现有能力 | 代码位置 | 对 M1 的约束 |
|---|---|---|
| 书架输入框只筛选项目名/路径 | `src/pages/Shelf/index.tsx` | 原输入框语义保持不变，不能无提示切换成代码搜索 |
| 项目主数据来自 SQLite | `src-tauri/src/commands/project.rs` | 后端按项目 ID 查询路径，不能信任前端传入任意根目录 |
| 编辑器接口只接收路径和编辑器路径 | `src-tauri/src/commands/system.rs` | M1 可打开文件，但不承诺可靠跳转行号 |
| 已有敏感文件规则及默认规则 | `src-tauri/src/commands/settings.rs`、`src/config/defaultSensitiveFilePatterns.json` | 该规则当前明确服务于“背景知识生成”，且默认排除测试、CI 和应用配置，不能静默套到纯本地搜索 |
| 已有任务所有权和取消范例 | `src-tauri/src/commands/git/clone.rs` | 搜索任务必须带唯一所有者，旧任务结束不得清掉新任务状态 |
| 已有跨平台进程树清理 | `src-tauri/src/process_guard.rs` | Git 文件枚举子进程的取消和应用退出清理由此收敛 |
| Rust 已直接依赖 `regex` | `src-tauri/Cargo.toml` | 正则模式使用本地确定性引擎，不引入 AI 或外部搜索程序 |
| Node sidecar 已使用 gitignore 语义 | `src-node/resume-agent/src/fs/projectBackend.ts` | 可借鉴边界，但 M1 不依赖 sidecar 存活 |

## 目标

- 在全部书架、指定分类或手选项目中搜索明确文本、正则和文件名。
- Git 项目默认搜索已跟踪文件，用户显式开启后才包含未跟踪且未忽略的文件。
- 非 Git 项目通过受控文件遍历参与搜索，不会因为没有 Git 而被静默排除。
- 结果按项目和文件分组、分批显示，并支持取消。
- 单项目失败不终止其他项目；取消、超时、截断、部分失败必须区分。
- 搜索内存由并发数、单行缓冲和结果上限决定，不随累计扫描文件总量线性增长。
- 未配置任何 AI Provider 时完整可用，执行过程不读取 Provider Store、不发起网络请求。

## Non-Goals

- 不做依赖和运行时清单搜索；该能力在 M2 实现。
- 不做自然语言、语义搜索、Embedding、向量库或 AI 自动扩词。
- 不建立全量内容索引，不持久化查询历史和搜索结果。
- 不做跨项目替换、批量编辑或自动修改代码。
- 不启动 LSP，不承诺精确引用、定义跳转和调用关系分析。
- 不搜索 Git 历史、提交内容、子模块内部仓库或被忽略文件。
- 不安装或依赖用户机器上的 `rg`。
- 不复用 AI Shell 或简历 Agent 作为搜索服务。
- M1 不新增通用“编辑器跳行协议”；只复用现有打开文件能力。

## 已确认产品决策

### 1. 入口与页面形态

首版入口放在书架现有“更多”菜单，名称为“跨项目搜索”，打开书架内的全屏覆盖层：

- 不增加侧边栏一级导航；它仍是书架能力，不是新的产品域。
- 不改变现有“搜索项目名称或路径”输入框的过滤语义。
- 覆盖层实现为独立组件，`ShelfPage` 只保留打开/关闭状态和初始范围传递，避免继续膨胀现有大组件。
- 从某个分类打开时默认选中该分类；从“全部”打开时默认选中全部项目。用户可在覆盖层改为手选项目。
- 关闭正在搜索的覆盖层时先发起取消；再次打开若旧任务仍在停止中，显示明确状态，不并发启动第二个任务。

等真实使用证明入口频率足够高后，再评估提升为书架头部独立按钮；M1 不提前占用头部空间。

### 2. 默认文件范围

| 项目类型 | 默认范围 | 开启“包含未跟踪文件”后 |
|---|---|---|
| Git 项目 | Git 已跟踪文件 | 已跟踪 + 未跟踪且未被 `.gitignore` 排除的文件 |
| 非 Git 项目 | 遵循忽略规则的受控文件遍历 | 行为不变，并在界面说明“非 Git 项目无跟踪状态” |

首版不提供“包含被忽略文件”选项。这里的“忽略”指 Git/.gitignore 与生成目录，不等同于简历模块的敏感规则。

### 3. 查询历史

首版只保存在当前覆盖层内存中，关闭即清空，不写 SQLite 或 JSON。只有真实使用反馈证明需要复用查询后，再为历史记录单独设计数量上限和敏感数据策略。

### 4. 搜索结果操作

- 点击结果使用项目已配置编辑器打开对应文件；没有项目级配置时沿用现有默认编辑器选择逻辑。
- 提供“复制相对路径”和“复制绝对路径:行号”。
- M1 不向任意编辑器拼接私有行号参数。当前接口无法确认 VS Code、JetBrains、自定义编辑器和 macOS `.app` 的参数能力。
- 后续如需跳行，先给编辑器配置增加可验证的能力类型，再扩展 `open_in_editor`；不能按编辑器名称模糊猜参数。

## 搜索行为

### 查询模式

| 模式 | 含义 | 空查询 |
|---|---|---|
| `text` | 对物理行做字面量匹配 | 拒绝启动 |
| `regex` | 使用 Rust `regex` 语义匹配物理行 | 拒绝启动；无效表达式在任务启动前报错 |
| `filename` | 对规范化后的项目相对路径做字面量包含匹配 | 拒绝启动 |

- 文本和文件名模式默认不区分大小写，用户可切换“区分大小写”。
- 正则模式的大小写选项在编译时生效，不允许表达式绕过资源上限。
- 路径在匹配与返回协议中统一使用 `/`，打开文件时再由后端基于项目根目录构造本机路径。
- 可选文件 glob 是额外的包含过滤器，不改变查询模式；最多 16 条。

### 文件枚举

1. 后端接收项目 ID 后从 SQLite 读取最新项目记录。
2. 项目根目录必须存在、是目录且可以规范化；失败只标记该项目。
3. Git 项目通过 Git 的 NUL 分隔文件列表获得已跟踪文件；开启开关时再加入未跟踪且未忽略文件。
4. 非 Git 项目使用支持 `.gitignore` 语义的 Rust 受控遍历；符号链接默认不跟随。
5. 每个相对路径先进行根目录边界、忽略规则、用户 glob、文件类型与大小校验，通过后才读取。
6. 路径来源不同但最终指向同一文件时去重；返回结果标明 `gitTracked`、`gitUntracked` 或 `filesystem` 来源。

Git 文件枚举允许调用系统 Git，因为 CodeShelf 已把 Git 作为项目管理基础能力；内容匹配仍由 Rust 完成，不能把用户查询拼成 Shell 字符串。

- Git 判定沿用现有项目语义：项目根目录直接存在 `.git` 文件或目录。书架项目只是某个父仓库的普通子目录时，按非 Git 项目搜索，不能越过书架根目录枚举父仓库。
- Git 的 NUL 分隔 stdout 必须边读边消费，stderr 也有固定上限；不能先用 `output()` 把超大文件列表完整收进内存再解析。
- 父项目搜索不递归进入其中的子模块仓库；子模块若作为独立书架项目加入，可在自己的范围内搜索。

### 忽略与本地数据边界

- `.git`、`node_modules`、`target`、`dist`、`build`、`.next`、`.cache`、`coverage` 作为默认生成目录排除项。
- 符号链接文件和目录首版均跳过，避免规范化后越出项目根目录。
- 搜索查询和预览只存在当前任务及覆盖层内存中，不写搜索历史、不写入应用日志、不发网络请求；日志只允许记录不含查询、预览和绝对路径的阶段、计数与错误类别。
- M1 不直接复用简历模块的敏感文件规则。该默认列表包含 `/test/`、`/.github/`、`application*.yml` 等正常代码检索目标，直接复用会产生用户不可见的漏搜。
- M6 若把搜索结果发送给 AI，必须在出站边界重新应用敏感规则，并让用户预览实际发送的文件和片段；不能因为 M1 本地可见就默认允许外发。
- 如果未来要为纯本地搜索提供用户排除规则，应单独命名为“本地搜索排除”，不能改变现有“背景知识敏感规则”的含义。

### 文本读取

- 文件逐个流式读取，不使用 `read_to_string` 读取完整文件。
- 首个读取块包含 NUL 时按二进制文件跳过。
- 单文件默认上限 8 MiB；超限计入跳过统计，不返回伪错误。
- 单个物理行缓冲上限 64 KiB；超长行不继续扩大缓冲，并计入跳过/截断统计。
- 单条预览最多 4 KiB，必须标识左右或编码截断。
- 非法 UTF-8 使用有损预览并标识 `encodingLossy`，但路径和行号仍保持可用。
- 内容结果的行号从 1 开始；列号从 1 开始，文件名结果的行列为空。
- 同一物理行有多个命中时只返回一条结果，列号指第一个命中，避免结果上限被重复位置快速耗尽；文件名模式每个文件最多一条结果。
- 超过 64 KiB 的物理行整行跳过并继续排空至换行符，不能用前 64 KiB 的局部内容产生可能误导的命中。
- 文件大小、二进制和物理行限制只约束内容模式；文件名模式仍可返回普通大文件或二进制文件的路径。

以上数值是首版工程常量，不放到设置页。只有基准测试证明不合适时才调整，避免为尚未出现的需求增加配置项。

## 资源与生命周期

### 固定上限

| 项目 | 默认/上限 |
|---|---|
| 同时搜索的项目 | 默认 2，硬上限 4 |
| 一次请求的项目数 | 200 |
| 查询长度 | 512 个 Unicode 字符 |
| 文件 glob | 16 条，每条 256 个字符 |
| 单项目结果数 | 500 |
| 全局结果数 | 2,000 |
| 事件批次 | 最多 50 条或约 50 ms 发送一次 |
| 单项目协作式时间预算 | 30 秒 |
| 整体协作式时间预算 | 120 秒 |

- 单项目达到 500 条后停止读取该项目，继续其他项目。
- 全局达到 2,000 条后停止全部项目，最终状态为 `truncated`。
- 超时是终止状态，不显示为“搜索完成”；项目超时与整体超时分别记录。
- 时间预算在文件之间和读取块之间检查。操作系统层已经阻塞的本地/NAS 文件读取无法被 Rust 线程硬中断，文档和界面不得把它宣传成绝对硬超时；Git 子进程仍必须可被主动终止。
- 前端只保留协议允许的最多 2,000 条结果；分组默认折叠，展开时分段渲染，不能一次为隐藏结果创建全部 DOM。

### 任务所有权

首版全应用同一时间只允许一个跨项目搜索任务：

- 前端生成 `searchId`，先注册事件监听，再调用启动命令，避免快速任务在监听建立前丢事件。
- 后端用单一任务槽原子完成“检查空闲 + 认领”；不得先检查后异步登记。
- 任务槽保存所有者 ID、取消标志和仍在运行的 Git 子进程 PID。
- 取消命令只能取消 ID 匹配的任务；旧任务结束只能释放自己的槽位。
- 取消信号在项目调度、文件之间、读取块/行之间和事件发送前检查。
- Git 子进程统一经过 `process_guard::configure` 或 `configure_std`，取消和应用退出使用 `process_guard::kill_tree`。
- 应用 `RunEvent::Exit` 中调用搜索模块的同步清理入口；窗口关闭只隐藏到托盘，不应取消搜索。
- 所有结束路径都发送一个终态事件，并释放任务槽；事件发送失败不能导致槽位永久占用。

## 前后端协议

以下是稳定的数据含义，不是最终 SQL；字段使用 `serde(rename_all = "camelCase")` 和 `specta::Type` 导出到前端。

### `ProjectSearchRequest`

```text
searchId
projectIds[]
mode: text | regex | filename
query
caseSensitive
fileGlobs[]
includeUntracked
```

- 不接受项目根路径、并发数和资源上限等由前端任意传入。
- 项目 ID 去重后不能为空；不存在的 ID 形成项目级失败信息，不能解析成任意路径。
- 请求通过结构和正则校验、成功认领任务槽后，启动命令才返回 accepted。

### `ProjectSearchMatch`

```text
projectId / projectName
relativePath
line / column
preview
previewTruncated
encodingLossy
source: gitTracked | gitUntracked | filesystem
```

返回 `projectName` 是任务启动时的显示快照；文件打开时仍按 `projectId + relativePath` 回到后端重新校验当前项目根目录，不能直接使用事件中的绝对路径。

### 事件

统一事件名：`project-search-event`。每个事件都包含 `searchId` 和 `kind`：

| `kind` | 载荷 | 用途 |
|---|---|---|
| `started` | 项目总数、应用后的上限 | 初始化进度 |
| `projectStarted` | 项目 ID、名称 | 显示正在搜索 |
| `matches` | 匹配批次 | 追加结果 |
| `projectFinished` | 扫描/跳过/命中数、耗时、是否单项目截断 | 项目完成对账 |
| `projectFailed` | 项目 ID、阶段、可显示错误 | 隔离失败 |
| `finished` | 终态与全局汇总 | 唯一终态 |

终态取值：`completed`、`partial`、`cancelled`、`timedOut`、`truncated`、`failed`。

- 有项目失败但至少一个项目正常结束时为 `partial`。
- 全部项目均失败且没有有效结果时为 `failed`。
- 用户取消、整体超时或全局截断优先显示对应终态，汇总中仍保留已发生的项目失败。
- 不把 Tauri 事件当成永久队列；覆盖层关闭会取消任务，首版不支持任务重连。

### 命令

- `start_project_search(request) -> accepted`
- `cancel_project_search(search_id) -> ()`
- `open_project_search_result(project_id, relative_path) -> ()`

打开结果必须由后端重新查询项目、规范化相对路径并确认目标仍在项目根目录内，再根据项目 `editorId` 和现有编辑器配置解析项目级或全局默认编辑器，最后调用现有编辑器打开逻辑。它不能接受前端拼出的绝对文件路径或可执行文件路径。

## 错误与状态展示

- 空查询、无效正则、请求超限、已有任务运行属于启动失败，直接返回具体中文错误，不创建后台任务。
- 路径失效、无权限、Git 文件枚举失败、单文件读取失败属于项目或文件级问题，不中止其他项目。
- Git 命令不可用时，Git 项目标记项目级失败；不能静默改为扫描整个工作区并声称等价。
- 文件在枚举后被删除属于跳过项；如果大量文件变化，汇总提示“搜索期间项目发生变化”。
- 界面必须同时显示匹配数、已完成项目数、失败项目数、跳过文件数和截断/取消状态。
- 前端捕获 Tauri 错误时使用现有 `errMsg`/字符串兼容方式，不能只判断 `instanceof Error`。

## 模块边界与影响面

### 预计改动

- 书架：新增覆盖层入口和初始分类范围传递。
- 前端搜索组件：查询表单、范围选择、事件聚合、结果分组和终态展示。
- Rust 搜索模块：协议、任务状态、项目查询、文件枚举、流式匹配、取消和汇总。
- `src-tauri/src/commands/project.rs`：向 crate 内暴露按 ID 读取项目的内部 helper，搜索模块不得复制项目 SQL 或新增同义 Tauri 命令。
- `src-tauri/src/handlers.rs`：注册 3 个新命令。
- `src-tauri/src/lib.rs`：应用退出时清理搜索子进程。
- `src-tauri/Cargo.toml`：允许为非 Git 遍历增加 Rust `ignore` 直接依赖；已有 JavaScript `ignore` 依赖不得删除或替换。
- `src/bindings.ts`：通过绑定导出测试重新生成，禁止手改。

### 不改动

- 不修改项目表、标签表或设置存储，不新增 migration。
- 不修改 AI Provider、Chat、Resume 或 Node sidecar 协议。
- 不修改现有书架项目名/路径筛选行为。
- 不写新的 JSON 数据文件。

### 约束核对

| 约束 | 结论 |
|---|---|
| 是否涉及 Windows 专有代码 | 不新增专有分支；复用 `process_guard`。仍需在 Windows 实机验证路径、取消与编辑器打开 |
| 是否涉及数据文件读写 | 只读项目文件和 SQLite；无应用数据写入 |
| 是否改动 Tauri 命令签名 | 是，必须重新生成 bindings |
| 是否新增前端轮询 | 否，使用事件；不触发 `document.hidden` 轮询问题 |
| 是否依赖 AI | 否 |

## 实施顺序

每一步单独验证，不把 M2 或 AI 增强混入：

1. **M1-A 协议与状态机**：定义类型、注册命令、完成任务认领/取消/终态与绑定导出；先用受控假结果验证事件竞态。

## 验证方式

### Rust 自动验证

- 纯函数：字面量/正则大小写、路径标准化、glob、忽略规则、二进制识别、预览截断。
- 状态机：并发启动只有一个成功；取消只影响所属任务；旧任务不能释放新任务槽。
- 资源边界：单项目/全局上限、单行上限、单文件上限、事件批次上限。
- 文件行为：中文与空格路径、无效 UTF-8、文件扫描中删除、符号链接越界、非 Git 项目。
- 终态：完成、部分失败、取消、超时、截断、全部失败各自只发一次。

执行：

```bash
cd src-tauri && cargo test --lib
cd src-tauri && cargo test --lib export_bindings
```

### 前端与构建验证

```bash
npx tsc --noEmit
cd src-tauri && cargo check
npm run build
```

如果新增 Rust 依赖，必须执行完整构建，确认 sidecar 和桌面应用依赖没有被误删或打包破坏。

### 人工验收样本

至少准备以下真实项目组合，不只使用临时空目录：

1. Git 项目：有已跟踪命中、未跟踪命中和 `.gitignore` 排除文件。
2. 非 Git 项目：包含嵌套目录和自定义 `.gitignore`。
3. 异常项目：书架路径已失效或无权限。
4. 路径样本：中文、空格、大小写相近文件名。
5. 内容样本：UTF-8、无效 UTF-8、二进制、超过 8 MiB、超过 64 KiB 的单行。
6. 本地数据样本：被 `.gitignore` 排除的 `.env`、意外已跟踪的 `.env`、测试和 CI 目录。

验收步骤：

- 清空 AI Provider 后完成文本、正则、文件名三种搜索，确认没有模型请求和网络请求。
- 默认搜索确认未跟踪命中不出现；开启开关后出现；被 `.gitignore` 排除的文件仍不出现。
- 确认已跟踪的测试、CI、应用配置可以本地搜索，查询和预览不写日志、不发网络请求。
- 搜索期间取消，确认 UI 收到 `cancelled`，Git 子进程及时退出，随后可以立即发起新搜索。
- 让一个项目失败，确认其他项目继续并最终显示 `partial`。
- 触发单项目和全局结果上限，确认界面明确显示截断而非完整完成。
- 点击结果确认打开正确文件；复制内容包含正确的项目相对路径和行号。
- 关闭窗口到托盘时任务继续；真正退出应用时搜索子进程被清理。
